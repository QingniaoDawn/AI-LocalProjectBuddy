一、程序概览

用一句话说清楚这个程序是干什么的。

整体用途

本地 Windows 桌面程序，让网页 AI（ChatGPT / Gemini / Grok）能像本地 Agent 一样读写你电脑上的项目文件夹。原始数据不上传第三方服务器。

核心亮点

零配置启动、Cloudflare 隧道自动暴露公网地址、跨模型同协议、工具集完整、绿色版免安装。

适用场景

让 AI 读/改本地代码、搜代码、跑命令、总结本地文档、做 patch 改写并自动跑测试。

不适用场景

不是网盘（不存文件同步）、不提供 GUI 可视化（AI 拿到的是文本结果）。

对接三种模型的共同点：都是把程序弹出的那个 https://xxx.trycloudflare.com/mcp/xxx 地址粘到网页端菜单里。差别只在网页端菜单位置不一样。

二、启动与准备

在你打开任何一个 AI 网页之前，先把程序跑起来并拿到连接地址。

1 启动程序

双击 本地项目小能手.exe（解压后的程序文件夹内），弹出主窗口。

首次启动会让你选择一个工作目录——这就是 AI 能访问的全部范围。建议选一个具体的项目子目录。

2 等待就绪，复制地址

界面状态显示"已连接 / Tunnel ready"后，点击右侧"复制地址"按钮，复制完整 HTTPS 地址。

地址形如：https://video-now-consult-ton.trycloudflare.com/mcp/93xxxxxxxxxx

注意：每次重启程序或网络抖动后地址都会变化。AI 那边如果连接不上，多半是地址过期，复制最新地址重新填一次即可。
3 确认地址完整

确保地址末尾带 /mcp/ 后缀，没有被聊天软件吞掉换行（建议粘贴到记事本先检查一下）。

三、对接 ChatGPT 网页版

必须先开启开发者模式，再以"自定义插件"形式加入隧道地址，最后在对话中 @ 即可调用。

1 开启开发者模式

路径：网页账户设置 → 账户安全与登录 → 高级安全设置 → 开发者模式，打开右侧开关。

不打开这一项，后面创建插件会一直失败。这是 ChatGPT 的强制前提。

2 进入插件页 → 点 + 号新建

左侧菜单点"插件"，进入插件页面，点击右上角的 + 号 弹出"新插件"窗口。

3 填写插件信息并创建
  • 名称：随便填，自己能认出来即可（如"本地项目"、"work"等）
  • 描述：留空
  • 连接：选"服务器 URL"，把隧道完整地址粘进去
  • 身份验证：选"无"
  • 勾选底部"我了解并希望继续" → 点击"创建"
常见提示：OpenAI 会显示"未对此 MCP 服务器进行审查..."——这是固定提示，勾选"我了解"即可，与程序无关。
4 权限放行

创建成功后进入插件详情页，点击右上角"允许所有操作"。

如果不放行，每次 AI 调用工具都会弹窗让你确认一次，体验非常差。

想要更安全？可以只勾选"低风险操作"（只读类）。但日常协作建议允许所有，省心。
5 新对话中 @ 插件 → 开始使用

新建对话，在输入框点 @，从下拉里选刚才创建的插件（如 qwe51），然后正常说话即可。

@ 一次即可，同一会话里多次调用工具不需要重复 @。

对接 ChatGPT 的流畅度说明

  • 单次调用延迟：约 2-5 秒（隧道 + ChatGPT 思考 + 工具执行），比手动切窗口快得多
  • 多文件改动：edit.patch 走事务（all-or-nothing），任何一步失败自动回滚
  • 隧道中断：ChatGPT 会显示工具调用错误，聊天本身不受影响；程序端会自动重连
  • 上下文限制：单条 1MB+ 的文件读取会迅速消耗 ChatGPT 上下文窗口，建议先用 files.search 定位再用 files.read 精确读
  • 免费账号限额：接入含文件类工具的连接器后，OpenAI 免费档会把该对话线程计入"涉及文件/图像"计量桶，比普通对话更容易触顶。触顶后开新对话线程即可重置；升级 Plus/Pro 可解除

四、对接 Google Gemini（Spark）

走"已关联的应用 → 自定义应用"路径，比 ChatGPT 少一步权限放行。

1 进入"已关联的应用"

路径：左下角账户设置 → 技能 → 左侧"已关联的应用"。

页面下拉找到"适用于 Spark 的自定义应用"区块（或直接点"自定义应用"按钮）。

2 粘贴地址 → 关联

在输入框里粘贴完整隧道地址（同样以 /mcp/ 结尾） → 点"下一个" → 点"下一步" → 勾选了解 → 点"关联"。

3 在 Spark 对话里 @ 调用

顶部切到 Spark 模式（不是普通对话） → 新建对话 → 输入框按 @ → 选刚添加的应用（如 Trycloudflare）即可。

五、对接 Grok

走"技能和连接器 → 连接器 → 新连接器 → 自定义"路径，三步搞定。

1 进入连接器页

路径：左侧"技能和连接器" → 中上"连接器"标签 → 右上"新连接器"。

2 选自定义 → 填地址

弹出层里点"自定义"（顶部第一项） → 名称随便填 → 把完整隧道地址粘到服务器 URL → 点"添加连接器"。

3 新对话 @ 调用

新建对话 → 输入框按 @ → 选刚创建的连接器即可使用。

Grok 的连接器添加是即时生效的，无需像 ChatGPT 那样单独做权限放行。

六、实际使用样例

对接完成后，你可以这样跟 AI 说话：

📖 搜代码

"帮我在工作目录里搜所有用了 md5 的地方，把文件路径和行号列出来。"

🔧 改代码

"把 src/a.js 里 function foo 改成 function bar，改完跑一下 npm test。"

📊 总结文档

"帮我把 docs/ 下的所有 markdown 文件总结成一份索引文档。"

🧪 跑命令

"执行 npm run build，把报错信息告诉我。"

AI 侧会自动调用的工具

工具名 作用
workspace.inspect检查工作区基本信息
files.list / files.recent列出文件 / 最近改动
files.searchripgrep 引擎搜索（带上下文）
files.read / files.read_many读单个/多个文件
files.write写入文件（自动备份）
edit.patch精确补丁（事务回滚）
dev.patch_and_test改完后自动跑测试
git.*版本控制工具组
shell.run / run.*隔离命令执行

七、使用注意事项

写在前面，比写在末尾更安全。

选工作目录要谨慎：程序只会让 AI 访问你选的那个文件夹。但你给 AI 的命令会让它真的执行——如果你让它删文件，它就会真删。建议用一个临时目录先试手。

路径与权限边界

  • symlink 越界、穿越目录会被直接拒绝
  • 不在工作目录内的文件 AI 完全看不到

隧道地址会过期

  • Cloudflare Quick Tunnel 是临时隧道，每次重启程序或网络抖动后地址都会变
  • AI 端连接不上时，多半是地址过期，复制最新地址重新填即可
  • 程序会自动尝试重连，并刷新界面地址显示

大文件性能

  • 默认不缓存 >8MB 的文件，超大文件 patch 走流式（内存占用降约 8 倍）
  • 100MB+ 单文件依然很慢，建议拆分成小文件

网络与重连

  • 隧道断开后界面会弹横幅提示"重连中..."，本地服务不中断
  • 重连成功后界面地址自动刷新
  • 短时间内多次断开会被识别为"网络不稳"，程序会快速失败，避免长时间卡"重连中"

ChatGPT 免费账号限额

重要：开启开发者模式 + 接入含文件类工具的连接器后，OpenAI 免费档会把该对话线程整体计入"涉及文件/图像"计量桶，比普通对话更容易触顶。触顶后开新对话线程即可重置；升级 Plus/Pro 可解除。此限制是 OpenAI 的计量策略问题，与本程序无关。

命令执行安全

  • 默认已剥离 authorization / cookie / bearer 等敏感环境变量
  • 但程序不会拦截 AI 调用 rm -rf / format 这种不可逆命令，请自己在选工作目录时就做好隔离

八、常见问题

? 程序双击无反应？

检查 Windows Defender / 杀毒软件是否拦截。首次启动需手动放行。

? 复制地址后 AI 端连不上？

依次检查：

  • 程序主窗口是否仍在前台运行（不是最小化到托盘被关了）
  • 复制的地址是否完整、是否带 /mcp/ 后缀
  • 本机网络是否能访问 trycloudflare.com（部分校园网/企业网会拦截）
  • 隧道地址是否已过期（重启过程序就会过期）
? AI 看不到某些文件？

检查：

  • "工作目录"是否选对了
  • 文件是否在 .git / node_modules / .cache 等忽略目录里
  • 文件名是否带特殊字符
? AI 改坏了文件，能恢复吗？

edit.patch 默认会生成同目录 .bak 备份；files.write 也是。直接把 .bak 改回原名即可。

? ChatGPT 弹"无法验证 MCP 服务器"？

正常提示，勾选"我了解并希望继续"即可。这是 OpenAI 的固定提示，与程序无关。

? 能同时多个人用吗？

可以，但需要把同一个隧道地址分别填到每个人的 ChatGPT / Gemini / Grok 里。注意隧道本身是共享带宽的，人多会慢。
